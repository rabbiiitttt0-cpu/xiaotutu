# 常见问题（FAQ / 故障排查）

按「现象 → 原因 → 解决」组织。排查任何问题时，第一反应是看日志：

```bash
docker logs xiaotutu-app --tail 100     # 后端日志（业务报错都在这）
docker logs xiaotutu-nginx --tail 50    # 网关日志（请求是否到达）
docker compose -p xiaotutu ps           # 容器状态
```

---

## 一、安装部署类

### 1. `curl http://127.0.0.1/api/health` 不通 / 健康检查失败

- **容器没起来**：`docker compose -p xiaotutu ps`，app 如果反复 Restarting，看 `docker logs xiaotutu-app`。冷启动加载 onnxruntime/opencv 可能要 1-2 分钟，别急着判死
- **80 端口被占**：`ss -lntup | grep :80`，改掉占用进程或改 `docker-compose.yml` 的 `ports: - "8080:80"`
- **db 一直 unhealthy**：PG 初始化慢，等 1 分钟；仍不行看 `docker logs xiaotutu-db`

### 2. `docker compose build` 拉镜像超时（国内服务器）

配置 registry mirror：`/etc/docker/daemon.json` 加 `"registry-mirrors": ["你的加速器地址"]`，`systemctl restart docker` 后重试。

### 3. 登录后所有 API 返回 401 / 页面一直跳登录

JWT 过期或 secret 不一致。重新登录即可；若反复出现，确认浏览器没禁用 Cookie/LocalStorage，或反向代理没有拦截 `Authorization` 头。

### 4. 上传文件报 413（Request Entity Too Large）

nginx 已默认放至 `client_max_body_size 1024m`，还报 413 说明前面还有一层代理（如 CDN/云负载均衡）限制，去那层调大。zip 包建议 ≤ 1GB。

## 二、图纸处理类（预处理队列）

### 5. 图纸状态一直是「处理中」不動

- 正常：大图渲染几分钟属正常，15 分钟内耐心等
- 超时：超过 15 分钟会被强制终止并标「失败」，error = `处理超时（>15 分钟），已终止`。原因基本是**内存不够**（大图 + 2C4G），参考第 8 条
- 真卡死：服务重启后会自动恢复队列（`processing`/中断的会重新入队），不用手工干预

### 6. 图纸「失败」，error = `DWG 转换失败`

LibreDWG 解析不了这个 DWG（常见于高版本 CAD 存盘、加密图纸、异常损坏文件）。**用 CAD 软件打开另存为 DXF（建议 R2013 格式）再上传**，成功率最高。若是加密/权限图纸，需先在 CAD 里解除。

### 7. 图纸「失败」，error = `处理进程异常退出（exit=…，可能内存超限）`

渲染进程被系统杀了（OOM）。大图（装修/暖通类几十 MB）在 2C4G 上容易触发。解法按优先级：

1. 升配到 4C8G（compose 里 app 的 `mem_limit` 同步调到 6g）
2. 把这张图在配置更高的机器上单独跑完再放回（参考「本地预处理」思路）
3. 用 CAD 把图里的无关图层/外部参照清理掉再传

> 单图失败不会影响队列里其他图纸（崩溃隔离设计）。

### 8. 预览图能看，但问答说"看不清/没有这张图的信息"

- 该图是纯扫描件 PDF？系统会自动 OCR 补文字层，若 OCR 也提取不到就真没内容——换文字版 PDF
- 标注太小：框选提问局部放大
- 多图图纸集问偏了：确认问题对应的图在集内；集内 >3 张时自动选图，答案会注明出自哪张

### 9. 「失败」error = `服务重启中断，请删除后重新上传`

部署/重启恰好打断预处理。图纸本身没问题，删除后重传即可（不会扣配额）。

## 三、使用类

### 10. 语音输入按钮点了没反应

语音识别用的是浏览器原生 Web Speech API：Chrome/Edge 的中文识别需访问谷歌服务（国内不通）；Firefox/Safari/微信内置浏览器干脆不支持。**推荐直接用文字提问**，效果一致。

### 11. 成员说「看不到项目图纸」

图纸需要管理员打开「近期常用」开关（项目管理 → 图纸管理 → 每行右侧开关），成员列表只显示 `就绪` 且开关打开的图。同时确认该用户已被加入项目成员。

### 12. AI 回答乱码/文不对题

- 先确认系统设置里配置的模型是**多模态视觉模型**（纯文本模型看不懂图）
- 检查 key 是否欠费/模型名是否拼错（审计日志页有每次调用的错误详情）
- 图纸太偏门时问题尽量具体（指图层/专业/部位）

### 13. 会话不见了

会话保留 5 天，过期自动清除，新建会话即可。重要结论建议及时导出交底文档。

## 四、运维类

### 14. 升级后想回滚

`deploy/deploy.sh` 部署失败会自动 `down` 回滚；手动场景：

```bash
cd /opt/xiaotutu   # 或你的部署目录
git checkout <旧版本 tag>
docker compose -p xiaotutu build && docker compose -p xiaotutu up -d
```

数据（`data/`、`pgdata/`）与代码分离，回滚不动数据。

### 15. 磁盘满了

主要是 `data/projects/` 下的图纸与渲染图。清理已删除图纸的残留：

```bash
docker exec xiaotutu-app python -c "清理脚本"   # 或直接定期备份后删除旧项目
```

临时渲染文件（DXF 中间件）用完即删，一般不是元凶；先 `du -sh data/*` 定位。

### 16. 改 `.env` 后没生效

`env_file` 只在**创建容器**时读取，改完必须重建：

```bash
docker compose -p xiaotutu up -d --force-recreate app
```

### 17. 忘了 admin 密码

数据库里重置（PG 示例）：

```bash
docker exec xiaotutu-db psql -U xiaotutu -d xiaotutu \
  -c "UPDATE users SET hashed_password='<bcrypt哈希>' WHERE username='admin'"
```

bcrypt 哈希可用任意 bcrypt 工具生成（如 `htpasswd -bnBC 10 "" 新密码 | tr -d ':\n'`）。
